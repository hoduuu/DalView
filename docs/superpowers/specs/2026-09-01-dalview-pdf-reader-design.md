# 달뷰 (DalView) — 가벼운 PDF 뷰어 설계 문서

- Date: 2026-09-01
- Status: Approved (design), pending implementation plan

## 배경 / 동기

사용자가 기존에 쓰던 PDF 리더(예: 알PDF류)가 너무 무겁고 광고가 많음. 순수하게
"보기"만 되는, 가볍고 빠른 Windows 데스크톱 PDF 뷰어가 필요함. 기존 사이드
프로젝트인 VideoPlayer(틀어봐), TabLauncher와 동일한 C#/WPF 스택으로 통일해
도구/노하우 재사용.

## 범위

**포함 (v1):**
- PDF 파일 열기 (파일 다이얼로그)
- 연속 스크롤 페이지 뷰, 줌 인/아웃, 페이지 번호로 이동
- 텍스트 검색 (전체 문서, 하이라이트 + 결과 페이지로 점프)
- 사이드바: 페이지 썸네일 탭 + PDF 내장 목차(Outline/Bookmark) 탭

**명시적으로 제외 (YAGNI):**
- 편집, 주석, 서명, 클라우드 동기화
- 인쇄 (필요해지면 후속으로 추가)
- 자동 업데이트 체크 등 네트워크 통신 일체 없음
- Windows 파일 연결/단일 인스턴스 (v1 범위 밖 — 필요 시 VideoPlayer 구현 재사용해 후속 추가)

## 기술 스택

- **언어/프레임워크**: C# / WPF (.NET), 기존 VideoPlayer·TabLauncher와 동일
- **패턴**: MVVM
- **PDF 렌더링 엔진**: PDFium (NuGet: `PdfiumViewer` 계열 — 유지보수 상태 확인 후
  `PdfiumViewer.Core` 등 최신 포크로 대체 가능). 크롬이 쓰는 오픈소스 PDF 엔진으로
  무료, 빠름, SumatraPDF류 경량 뷰어들이 채택하는 방식과 동일 계열.

## 아키텍처 / 성능 설계

체감 속도가 느려지는 원인은 "기능 개수"가 아니라 "전체 페이지를 한 번에 렌더링"하는
구현 방식이므로, 아래 가상화 전략으로 페이지 수와 무관하게 빠른 반응성을 확보한다.

- **메인 뷰**: `VirtualizingStackPanel` 기반 연속 스크롤. 화면에 보이는 페이지
  ±1페이지만 실제 비트맵으로 렌더링하고, 나머지는 자리(placeholder)만 차지하다가
  스크롤이 다가오면 그때 렌더링.
- **썸네일 사이드바**: 저해상도 썸네일을 스크롤 시점에 지연 생성(lazy) +
  메모리 캐싱. 전체 페이지 썸네일을 앱 시작 시 한 번에 만들지 않음.
- **검색**: 백그라운드 `Task`에서 텍스트 추출/매칭 수행, UI 스레드 블로킹 없음.
  결과 클릭 시 하이라이트 + 해당 페이지로 스크롤 이동.
- **목차(Outline)**: PDFium이 제공하는 문서 내장 북마크/아웃라인 트리를 그대로
  사이드바 두 번째 탭에 표시. 없으면 탭 비활성화.

## UI 구성

- **툴바**: 파일 열기, 줌 % 표시/조절, 페이지 번호 입력창(현재/전체), 검색창
- **왼쪽 사이드바**: [썸네일] / [목차] 탭 전환
- **메인 영역**: 연속 스크롤 페이지 뷰

## 에러 처리

- 손상되었거나 열 수 없는 PDF: 다이얼로그로 알리고 앱은 유지 (크래시 없음)
- 암호로 보호된 PDF: 비밀번호 입력 프롬프트 (v1 최소 지원 — 실패 시 명확한 안내)

## 테스트 방향

- PDFium 래퍼 연동부는 실제 샘플 PDF(짧은/긴/암호 걸린 문서)로 수동 검증
- 가상화 렌더링은 대용량(수백 페이지) 샘플로 스크롤 반응성 확인
- MVVM 뷰모델 단위 테스트: 페이지 이동, 줌 상태, 검색 결과 인덱싱 로직
